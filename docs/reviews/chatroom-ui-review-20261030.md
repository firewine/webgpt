## 적용할 방향

현재 작업실의 대화창을 단톡방처럼 발전시킨다. 왼쪽에서 누가 참여하는지 보고, 중앙에서 누가 누구에게 말하는지 읽고, 오른쪽에서 관련 자료·비교·실행 상태를 연다. 사용자가 계속 지시하지 않아도 참여자가 상대 말을 받아 질문·반응·다른 화제로 이어가는 자율 수다를 추가한다. 기존 주제 토론·긴 전체 발언 재분석·검증·Codex 환류와 같은 앱 안에서 제공한다.

첫 번째 첨부 이미지는 참여자 아바타·이름·상태와 참여 스위치, 중앙 말풍선·인용 답장·멘션·반응·하단 입력창, 오른쪽 작업공간·메모·사용량 패널이다. 두 번째 이미지는 3D 블록 건축 화면이다. 사용자가 제외한 지도·건물·좌표·블록·게임 월드·카메라·해당 도구/프롬프트는 도입하지 않는다. 그래픽 취향과 화면 배치를 참고하며 외부의 인물 그림·로고·캐릭터를 복사하지 않는다.

## 화면 구성

| 영역 | 추가할 동작 | 유지할 기능 |
| --- | --- | --- |
| 왼쪽 참여자 | 아바타/색·별칭, 계정 구분, 실제 응답/대기/오류, 향후 발언 참여 토글, 수다 시작·정지와 속도 | GPT 계정 분리, model/effort 설정, 연결 상태·관측 시각, 토의 기록 |
| 중앙 단톡방 | 말풍선, 작성자·시각·모드, 인용 답장·@멘션, 사용자 중간 참여, 현재 응답, 새 메시지로 이동 | 단계·revision·세대·원문 ID, 독립 초안/라운드 공개 규칙, 전체 발언·미확인 기록 |
| 오른쪽 보조 패널 | 선택 메시지의 원문·근거·자료, 사용량, 비교/검증/실행 상세를 필요할 때 표시 | 로컬 파일 snapshot과 허용 경로, observed/reported/not_run, 승인·실행 결과 |
| 방 설정 | 주제 토론/자유 대화 선택, 참여자·진행 한도·속도·휴면, 아바타/말투 설정 | 인증·연결은 기존 설정 화면, 상태·맥락·권한 조회, Chrome 로그인 보조 화면 |

넓은 화면에서는 3개 영역을 함께 제공하고 오른쪽 패널은 접을 수 있게 한다. 좁은 화면에서는 대화가 중앙을 차지하며 참여자/자료는 drawer·탭으로 연다. 고정 입력창이 한국어 입력기·가상 키보드를 가리거나 긴 코드/URL 때문에 페이지 가로 스크롤이 생기지 않게 한다. hover만으로 답장·반응 버튼을 숨기지 않고 터치·키보드에서도 접근할 수 있게 한다. 어두운 테마와 동작 줄이기도 검토 범위다.

장문은 몇 줄 미리보기와 펼치기로 읽기 편하게 하되 전체 본문·인용 출처·수정/비교를 유지한다. 사용자가 과거 메시지를 읽는 중이면 강제로 아래로 스크롤하지 않는다. SSE 재연결 때 message/event ID로 중복 제거하고 답장 대상과 펼침·스크롤 위치를 보존한다. `대기`, 실제 요청 전송 중, 실제 stream 수신, 오류/미확정 상태를 구분하고 캐릭터가 활동하는 모습으로 여러 모델 동시 실행이나 검증 성공을 꾸미지 않는다.

## 자유 대화와 주제 토론

| 구분 | 주제 토론 | 자유 대화·자동 수다 |
| --- | --- | --- |
| 목적 | 독립 초안→상호 검토→근거→수정→비교 | 서로 말을 받아 질문·농담·아이디어·화제를 이어감 |
| 입력 공개 | 기존 초안·같은 라운드 응답의 공개 장벽 유지 | 해당 방에서 공개된 대화와 선택 자료만 다음 발언에 제공 |
| 응답 | 기존 claims/reviews/verification 구조 | 원문 text, replyTo/수신 참여자 ID, say/pass 등을 검증하는 별도 응답 계약 |
| 발언 배정 | 기존 단계·라운드 scheduler | 지목/답장 우선 + 미발언 참여자 순환, 동일한 단일 실행 슬롯 |
| 출력 의미 | 근거별 검증 상태와 비교 결과 | 대화·의견이며 별도 확인 없이는 사실 검증으로 승격하지 않음 |
| 종료 | 토의 절차 또는 설정 예산 | 정지·시간/호출 한도·휴면·연속 pass·연결/전송 차단 |

자유 대화는 주제를 매번 새로 주지 않아도 선택한 참여자가 이전 공개 발언을 읽고 실제 응답한다. 사용자는 중간에 한마디하거나 @참여자로 부르거나 기존 발언에 답장할 수 있다. 대화 속도는 다음 dispatch까지 최소 대기 간격을 조절하며 사고 깊이·모델·긴 답변을 자동으로 줄이지 않는다. 침묵 시에는 실행 가능한 한 명만 깨우며 pass도 실제 호출이므로 예산에 포함한다. 연속 pass/같은 내용 반복에는 대기 증가·휴면을 사용해 빈 호출 루프를 막는다.

신규 자동 수다는 기본 꺼짐으로 두고 사용자가 한 번 시작하면 설정한 범위 안에서 사용자 중계 없이 진행한다. 시작 화면에는 호출·시간 한도, 계정/모델/effort, 자동 휴면을 함께 표시한다. 구현 초안은 30분·최대 30호출, 속도별 완료 후 최소 대기 5/15/45초, 침묵 깨기 120초, 연속 pass 3회 후 휴면이다. 구체 값은 구현 시 fake clock·사용성 검사로 조정할 수 있으며 무제한·자동 재시작을 기본으로 하지 않는다. 사용량은 provider가 보고한 값만 표시하고 미제공을 0원·정확한 잔여율로 꾸미지 않는다.

초기에는 자유 대화와 주제 토론을 같은 활성 방에서 동시에 돌리지 않는다. 모드·참여자 변경은 진행 중인 발언의 확정 경계에서 반영하고 미확정 전송이 있으면 대조를 먼저 한다. pause/정지는 새 발언을 막고 진행 중 외부 Codex 실행 취소와 구분한다. 페이지 새로고침·다른 기기 접속·SSE 재연결·타이머 재등록이 같은 발언을 다시 보내지 않아야 한다. 재시작 시 남은 시간·호출 수와 원래 attempt를 복구하고 놓친 타이머를 한꺼번에 만회 호출하지 않는다.

`이 수다를 주제로 토론하기`는 사용자가 고른 공개 메시지/자료를 공통 입력으로 고정하고 새 주제 토론을 생성하는 흐름으로 한다. 기존 자유 대화 원문은 유지한다. OAuth/API의 새로운 토론 context와 기존 browser agent 대화를 구분하고, dot/Muse의 대화는 지우거나 다른 계정으로 옮기지 않는다. 기존 browser가 이미 읽은 수다를 잊었다고 주장하지 않으며 이번 토론의 새 초안을 미리 공유하지 않았다는 독립성 범위를 표시한다.

멘션·replyTo는 같은 방·허용 공개 범위에 실제 존재하는 참여자/메시지 ID인지 검사한다. 초기 초안을 답장/미리보기/메모 경로로 다른 토커에게 누출하지 않는다. 말투·아바타·반응은 실행 권한이 아니며 단톡방 말 한마디로 새 Codex scope나 파일 쓰기를 허용하지 않는다. 실제 검증/개발이 필요하면 현재 task·binding·승인 계약으로 연결하고 R2/R3의 실파일 실행 선행 조건을 유지한다.

CHAT-01은 기존 데이터 표시 개선으로 먼저 진행할 수 있다. CHAT-02/03에서 메시지·실행 상태와 idempotency를 먼저 정하고, CHAT-04에서 주제 토론과의 경계를 검증한다. 이미 구현된 전원 장문 재분석을 새 수다 기능으로 다시 세지 않는다. 실제 계정 MVP-1을 모든 꾸미기·이모지·이미지 생성 완료 뒤로 미루지 않으며 GPT 인증은 사용자가 귀가 후 진행한다는 기존 일정을 유지한다.

공유 메모·장기 개인 기억·이미지 생성·스티커 제작은 별도 후속 범위로 둔다. 메모를 추가할 때는 공개 메시지에서 만든 공유 메모와 계정별 비공개 이력을 구분하고 원문 출처·적용 세대를 남긴다. 기존 ChatGPT/dot 기억을 로그인만으로 가져오거나 모든 참여자에게 공유했다고 주장하지 않는다. 범용 파일 생성·실행 가능한 HTML 작업공간·웹 공개 접속·외부 CDN 의존은 이번 GUI 참고에서 자동 도입하지 않는다.

이번 산출물은 이 검토서와 개발/토론/UI/실행 순서의 계획 변경이다. 제품 구현·시안 화면·실계정 수다의 완료 표시는 하지 않는다. 외부 코드·이미지는 /tmp에서만 읽었고 서비스·DB·계정·Chrome·허용 경로는 변경하지 않았다. 변경은 작업 브랜치 PR로 제출하며 사용자 병합 정책을 유지한다.
