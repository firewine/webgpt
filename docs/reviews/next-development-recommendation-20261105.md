## 3. 우선순위1의 최소 변경안 — 승인

문제는 topic이 기존 Wiki를 읽기는 하지만 종료 결과를 다시 Wiki로 남기지 않는다는 것이다. 모델에게 매번 수동으로 “위키에 기록해”라고 요청하는 방법은 현재 코드로 가능하지만 운영이 사용자의 중계에 의존한다. **기존 공개 결과를 결정적으로 투영하는 작은 연결 모듈**을 추천한다. 추가 요약 모델 호출/새 provider 없이 이미 수락한 종합·반론·불확실성과 원문 참조를 기록한다.

사용자가 “1번 개발 승인”으로 아래 최소안의 개발을 승인했다. 생성 시 범위를 고정하고 게시/보류 상태를 보여주기 위한 optional `Discussion.wikiPublication` metadata는 기존 JSON에 추가한다. 새 SQL 테이블·인증·공개 endpoint·source kind는 추가하지 않는다. 나머지 추천과 실계정 호출/서버 적용은 이 승인에 포함하지 않는다.

- 방에 명시 연결된 주제가 `completed` 또는 `partial`로 확정되고 공개 가능한 원문이 투영된 경계에서 한 번 게시한다. `partial`에는 부분 결과/미해결/미실행을 명시하고 없는 결론을 만들지 않는다. cancelled·blocked·진행/미확정 상태의 게시0.
- `discussionId + revision`을 원래 입력 digest와 함께 게시의 고정 식별 근거로 삼는다. 재접속·반복 tick·재시작이 새 Wiki 버전을 만들지 않는다. 소유자/AI 편집 이후 원래 게시를 재적용해 덮어쓰지 않는다.
- 기존 `sourceRefs.kind=message`로 공개 topic 투영 메시지를 참조하고 같은 Wiki CAS/출처 검사·Store transaction·SSE를 재사용한다. 새 SQL 테이블·인증·모델 응답 계약은 예상하지 않는다. 새 source kind/공개 API가 불가피해지면 확대 전에 영향안을 다시 보고한다.
- 문서의 상태는 기존과 같은 `reported`다. 동의·실행 관측·주장 검증·반론을 구분하고 private 초안/같은 라운드의 미공개 응답·타 방 자료를 넣지 않는다.
- 독립 주제는 대상 방이 명시되지 않은 상태에서 임의 배정하지 않는다. 과거 완료 토의 일괄 이관도 별도 결정 대상이다. 현재 실패한 OAuth 토의의 작성자/응답을 웹 GPT로 바꾸지 않는다.
- 기존 본문/출처/context 한도를 유지한다. 초과 시 원문을 보존하고 선택/기록 보류 사유를 표시하며 묵시적 잘림·추정 요약·자동 모델 재전송으로 우회하지 않는다. 누적 Wiki의 자동 relevance 선택/압축은 이번 최소안 밖의 후속 제안이다.
