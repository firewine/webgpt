## 구현 결과

처음 실행할 수 있는 코드가 없던 저장소에 Node.js 24·strict TypeScript 단일 프로젝트를 추가했다. `npm ci → npm run build → npm start` 후 진단 화면에서 테스트 참여자 A/B를 선택해 한국어 메시지를 보내고, 서버의 모의 응답·요청 ID·완료 상태를 확인할 수 있다.

- Core의 Participant/Turn과 provider 계약, fake adapter, HTTP/web 계층을 분리했다. 실제 OAuth/API/Chrome 계약은 아직 가정해 구현하지 않았다.
- `/health`, `/api/participants`, `/api/turns`와 명시한 웹 asset만 제공한다. 실행 시 외부 패키지나 모델 credential이 필요하지 않다.
- 기본 loopback 바인딩, 설정 검증, 입력·본문 크기 제한, 단일 활성 요청, 완료/실패 분리, 시작·종료 처리를 추가했다.
- 로그는 정해진 메타데이터만 남긴다. 입력·응답·credential·원본 오류를 직렬화하지 않는다.
- 화면에 모의 응답임을 명시했다. 한국어 입력·참여자 변경·실행/완료/실패/미확인 상태, 입력 보존, 최신 응답 스크롤을 제공한다. 메시지는 HTML로 해석하지 않는다.
- `README.md`, 설정 예제, lockfile, 기본 검사와 브라우저 검사 명령, GitHub Actions 워크플로를 추가했다.

서버에는 대화 기록을 저장하지 않는다. 화면의 최근 20개 요청은 새로고침하면 사라진다. 같은 참여자에게 다시 보내는 메시지도 이 단계에서는 독립 요청이다. 영속 맥락·journal·SSE·자동 토론은 후속 작업이다.

HTTP 검사에는 잘못된 설정·JSON·입력·본문 크기, 알 수 없는 참여자, 다른 origin, 동시 요청 409, provider 실패 502, 중단 상태, 실패 후 다음 요청, 비밀성 원문 로그 제외가 포함된다. 브라우저에서는 실패 후 입력 유지, 연결 중단을 미확인으로 표시하고 재전송하지 않는 동작, 새로고침 시 기록 초기화, 서버 확인 실패 후 수동 재연결도 검사했다.

### 브라우저 검증 환경의 차이

이 환경의 Playwright 기본 Chromium 다운로드 URL은 ZIP 대신 `Site Unavailable` HTML을 반환했다. 기본 브라우저 설치는 실패했으며 이를 제품 테스트 성공으로 바꾸지 않았다. 검증용으로 npm 배포의 `@sparticuz/chromium@153.0.0` 실행 파일을 별도 준비하고 `WJ_TEST_CHROMIUM_EXECUTABLE`로 지정해 동일한 브라우저 테스트를 실행했다. 이 패키지와 실행 파일은 프로젝트 의존성이나 Git에 포함하지 않았다.

한국어 캡처를 위해 검증 환경에 Noto Sans KR 글꼴을 설치했다. 제품 웹 화면은 외부 폰트 요청 없이 시스템 글꼴을 사용한다. 화면 캡처는 `npm run test:browser` 실행 시 `test-results/diagnostic-1440.png`, `test-results/diagnostic-390.png`로 재생성되며 Git에서 제외한다.
