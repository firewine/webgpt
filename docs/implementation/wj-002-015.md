## 구현 계약과 운영 주의점

- 데이터·journal·idempotency를 같은 SQLite transaction으로 저장한다. command key가 같고 입력이 다르면 409이며 미확인 응답은 새 호출로 되돌리지 않는다.
- 연결 secret은 UI snapshot·journal·기본 로그에서 제외하고 AES-GCM vault에 둔다. 소유자 session hash와 scoped grant hash만 DB에 저장한다.
- source 조회는 공개 IP만 허용하고 DNS를 고정한다. private/loopback/Tailnet/metadata 주소와 redirect 재바인딩을 막는다. 받은 원문, digest, 발췌 여부를 기록하고 참/거짓 판정으로 바꾸지 않는다.
- 실제 Codex 0.165.0에서는 `approvalPolicy=untrusted`, `approvalsReviewer=user`다. 문서와 설치 schema가 다른 항목을 대조해 수정했다. 보호 경로는 bubblewrap으로 별도 가린다.
- Codex의 같은 repo root 실행은 앱 안에서 직렬화한다. 다른 앱/CLI가 같은 세션을 쓰지 않는 운영 소유권 인계가 필요하다.
- dot에 MCP 실행 grant가 있는 검증 과제는 dot의 prompt를 직접 접수한다. 같은 과제의 재접수는 같은 job으로 귀결되며 결과가 끝난 다음 재검토한다. grant가 없는 연결은 Core가 구조화된 검증 제안을 등록된 binding에 전달한다.
- MCP Events는 새로운 MCP 2.0 이벤트 계약 및 계정 capability 검증 전까지 비활성이다. 완료 통지는 Core 관측→기존 browser 재검토 경로를 사용한다. 현재 구현을 Events 구독·webhook 구현으로 표시하지 않는다.
- checkpoint는 원문 ID/해시·발췌 표시·반론·미확인·예산·pending job을 보존한다. provider가 context 교체를 제공하지 않는 기존 browser 대화는 전환을 거절한다.

설계 결정은 [ADR](../adr/0001-workspace-runtime.md), 배포와 실환경 검증은 [운영 절차](../operations-runbook.md)를 따른다.
