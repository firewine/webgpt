실제 dot에게22:28~22:34 실행의 마지막 정상 페이지·답변 생성/submit 여부·오류를 새 도구 실행 없이 조회하도록 요청했다. 이 기록을 받기 전 생성 완료·submit 미실행·감시 종료를 추정하지 않는다. 원래 미확정 요청은 명시 재시도/skip으로 바꾸지 않았다.

## 재현·수정한 별도 결함

`scripts/mcp-stdio.mjs`는256,000bytes를 넘는 줄을 **JSON의 id를 읽기 전에** 거절했다. catch는 `message.id`가 있어야 오류를 내보내므로 해당 줄을 조용히 버리고 다음 요청으로 넘어갔다. 예를 들어90,011자 한글 reply는100,000자 제한보다 짧아도 요청의 UTF-8 bytes가256,000을 초과할 수 있다. 수정 전 실제 전달기 회귀에서id41 오류가 사라지고 다음 ping42만 성공하는 현상을 재현했다. **실제11월10일 submit이 이 크기였다는 증거는 없다.**

수정은 다음 범위다.

- 전달/HTTP 제한256,000bytes와25초 전송 timeout은 유지한다. 초과 입력을 서버로 보내지 않는다.
- 오류의 올바른 최상위 ID를 읽기 위한 JSON 검사만1,024,000bytes까지 제한한다. 이 안의 유효 request는 기존 `-32603` 오류와 같은 ID를 받으며, 다음 정상 요청은 계속 처리한다.
- 유효 notification에는 응답하지 않는다. 중첩 ID/객체 ID를 반환하지 않고, 파싱 불가 입력은id:null의 parse error다.
- 검사 상한을 더 넘으면 EOF/exit1로 연결을 종료한다. 무제한 JSON.parse나 불명확한 notification 응답을 피한다. 이 경우 전달기 재시작은 운영 대조 후 수행하며 자동 재전송을 추가하지 않는다. Node readline은 여전히 줄 전체를 버퍼링하므로 이것을 스트리밍 메모리 상한 구현이라고 표시하지 않는다.
- `src/`·DB·기존 도구 입력/페이지·claim/submit·300초·안전 경계·Muse/5개 답변은 변경하지 않는다. 크기 초과 오류 회귀는 전달기11개 fixture로 확인했다. 아래 진단은 별도 승인 뒤 추가한 범위다.

## 승인된 선택형 메타데이터 진단

2026-11-13 사용자가 [영향 검토서](../reviews/dot-call-observation-impact-20261113.md)의 계획 개정·개발을 승인했다. 기존300초·API 예산·MCP 입력/DB/get0 writes를 유지하며 D4 운영 진단과 R8 검사만 보완한다. 운영 활성화·실계정 재호출은 포함하지 않는다.

- `scripts/mcp-call-trace.mjs::createMcpCallTrace`가 요청 도착/응답 구성의 시각·소요 시간, 허용된 도구 분류·요청 ID SHA256 참조·페이지 수·바이트 수·HTTP/RPC 오류 분류만 stderr에 기록한다. 응답 페이지의 v1/v2 표현을 호출마다 새로 해석한다. 요청/결과 객체를 그대로 기록하지 않는다.
- `scripts/mcp-stdio.mjs`는 `WJ_MCP_TRACE=summary`일 때만 기록한다. 기본·다른 값은 off다. 정상 응답뿐 아니라 HTTP401/429, 전송 timeout, 잘못된 JSON, 크기 초과·연결 종료를 구분한다. 선택 기능이 자동 재시도를 만들지 않는다.
- stderr 실패와 로그 적체는 요청 처리·종료를 중단하지 않는다. POSIX pipe에 직접 쓰고 전송 불가/짧은 쓰기는 진단을 중단하며 별도 쓰기 대기열을 만들지 않는다. 로그가 누락·잘릴 수 있으므로 기록 부재를 미실행으로 판정하지 않는다. page 반환/`ok`는 원격의 읽기·분석 완료나 답변 수락 증거가 아니다. 실제 완료는 기존 reply/receipt와 대조한다.
- 변경은 전달기/helper·검사2개·SSOT/운영/영향/실측 문서로 구성된다. 첫 CI 실패 때문에 기존 검사 fixture2개도 별도 보완했다. 운영 코드/API/UI/마이그레이션·호스트 설정 추가0이다.
- 롤백은 선택 환경 변수 제거와 기존 전달기 사용이다. 실제 적용 전 정상 RPC stdout/전달 횟수 동일성과 로그의 비밀 제외를 합성 검사로 확인했다.
